大型語言模型代理人

LLM-Agent工具使用規劃記憶

大型語言模型代理人

概念

LLM Agent 將語言模型放在一個能感知任務狀態、選擇工具、執行行動並依結果繼續或結束的流程中。模型生成文字只是其中一環；工具介面、執行環境、狀態／記憶管理與結果驗證共同決定系統能力。

來源中的實例：FinAgent

李旻珊2026-LLM-Agent股票技術分析 描述的 FinAgent 以 GPT-4o 作推理協調者，使用 ReAct：推理與行動迴圈 依問題需求取得行情與指標，Node.js 執行計算程式，並以 Agent 反思與檢索式記憶 處理失敗修復及跨任務記憶。分析模組將計算結果轉為自然語言解釋。

這種分工把「資料是否新鮮」、「計算是否正確」和「解釋是否有用」拆成不同可檢查環節。論文的對照設計顯示工具組與程式執行對該研究任務有明顯效益；記憶機制則因基線任務全數成功，未測出增量效果。

設計／評估問題

  • 工具能否提供可驗證、具時間戳與明確資料來源的結果？
  • Agent 是否能正確決定何時需要工具，以及如何處理工具錯誤？
  • 哪些工作交由確定性程式處理，哪些工作留給模型做語意判斷？
  • 是否有端到端任務成功率、基線與消融對照，而非僅展示對話案例？
  • 記憶是否真的在新任務、長期追蹤中改善表現？
  • 對使用者呈現的信心、限制與來源是否足以校準信任？

邊界

單一系統原型與小樣本概念驗證不能代表 LLM Agent 在其他模型、資料來源或金融任務中的一般表現。參見 LLM 金融技術分析 與 以 LLM Agent 為核心之股票技術面分析輔助系統。
